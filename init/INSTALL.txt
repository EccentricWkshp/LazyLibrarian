Running LazyLibrarian as a service
==================================

Docker
------

The easiest way. The image is eccentricwkshp/lazylibrarian on Docker Hub, for amd64 and
arm64, and docker-compose.yml in the main folder is an example to start from:

  docker compose up -d

Settings, the database, cache and logs go in /config. PUID and PGID set the user and group
LazyLibrarian runs as, so the files it writes belong to you (run `id` to see yours). Give
it the same paths to your downloads as your download client uses. Update by pulling the
new image: docker compose pull && docker compose up -d

The same image is published as ghcr.io/eccentricwkshp/lazylibrarian. Use that one if you hit
Docker Hub's limit on pulls without a login.


systemd (Debian, Ubuntu, Fedora, Arch and most other current Linux systems)
---------------------------------------------------------------------------

As root, or with sudo. This puts LazyLibrarian in /opt/LazyLibrarian and its settings,
database and logs in /var/lib/lazylibrarian, the paths lazylibrarian.service expects.
LazyLibrarian needs Python 3.11 or newer, and libmagic (apt install libmagic1).

  useradd --system --home-dir /var/lib/lazylibrarian --create-home --shell /usr/sbin/nologin lazylibrarian
  git clone https://github.com/EccentricWkshp/LazyLibrarian.git /opt/LazyLibrarian
  python3 -m venv /opt/LazyLibrarian/.venv
  /opt/LazyLibrarian/.venv/bin/pip install -r /opt/LazyLibrarian/requirements.txt
  # only needed for updates from the web interface
  chown -R lazylibrarian:lazylibrarian /opt/LazyLibrarian

  cp /opt/LazyLibrarian/init/lazylibrarian.service /etc/systemd/system/
  systemctl daemon-reload
  systemctl enable --now lazylibrarian

Then open http://<this machine>:5299 to set up a login.

The lazylibrarian user needs write access to your library and download folders. Adding
it to the group that owns them works, the service runs with umask 0002 so the files
it writes stay writable for that group:

  usermod -aG <group> lazylibrarian

To use other paths or another user, override the defaults rather than editing the file:

  systemctl edit lazylibrarian

  [Service]
  User=me
  Group=me
  ExecStart=
  ExecStart=/home/me/LazyLibrarian/.venv/bin/python /home/me/LazyLibrarian/LazyLibrarian.py --datadir /home/me/.lazylibrarian --nolaunch

(the empty ExecStart= line is needed to replace the command rather than add another)

Logs: journalctl -u lazylibrarian, or Logs in the web interface.


SysV init (older systems without systemd)
-----------------------------------------

Edit lazylibrarian.default if necessary, the init script should not need changing.
The defaults expect LazyLibrarian in /opt/lazylibrarian, with config, database and
logs in the home folder of the user it runs as.

  cp lazylibrarian.initd    /etc/init.d/lazylibrarian
  cp lazylibrarian.default  /etc/default/lazylibrarian
  update-rc.d lazylibrarian defaults
  /etc/init.d/lazylibrarian start

On FreeBSD use freebsd.initd instead.
